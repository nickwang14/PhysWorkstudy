# When to Change the Plan

## Overview
Program changes should happen for a reason. A good plan changes when the goal, recovery status, or life situation demands it—not because the user feels restless or unsuccessful.

## Key Ideas
- change should be tied to measurable signals, not random intuition
- plan changes should protect consistency and recovery, not chase novelty
- if the plan is working, the learner should not change it for the sake of change
- a better plan is one that remains explainable to the user

## Connection to Practice
This subchapter teaches the learner to reason about progression, not just follow a static checklist. It is a practical bridge between instruction and real user behavior.

## Knowledge Check
What signal should trigger a plan change: low energy for one day, or a pattern of poor recovery over multiple weeks?

## Scenario
A learner works through a case involving subchapter 5 when to change the plan. They should explain what changes, why it matters, and what the next training decision should be.
